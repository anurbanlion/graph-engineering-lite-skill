# Use Cases - `search`

## Route: `/demo/catalog` (and Universal Search Overlay)

### 1. Service Operations (`apps/storefront/apis` / `@chiki/search` / Supabase RPCs)

| Scenario | Service Call | Returned Front Type | Implementation Suggestion | Status |
| :--- | :--- | :--- | :--- | :--- |
| **Cargar resultados del catálogo con filtros activos**<br/>**Given:** El visitante navega a `/catalog` con parámetros de búsqueda (`q`, `game`, `expansion`, `type`, `stock`).<br/>**When:** El Server Component ejecuta `searchCatalogResult(...)` vía `@chiki/search`.<br/>**Then:** Se ejecuta la RPC `search_catalog`, se normalizan y mapean las filas a `CatalogSearchResult[]`, y se extraen las expansiones disponibles. | `searchCatalogResult(params)` | `SearchCatalogOutcome` (`{ status: 'ok'; items: CatalogSearchResult[]; hasMore: boolean }`) | Server Component parallel read (`Promise.all` con usuario y carrito) con revalidación dinámica (`force-dynamic`). | Validated |
| **Fallo o timeout en consulta del catálogo**<br/>**Given:** La consulta al catálogo excede el `statement_timeout` o la base de datos responde con error.<br/>**When:** Se procesa el resultado devuelto por `@chiki/search`.<br/>**Then:** Se retorna `{ status: 'error', errorCode }` permitiendo al cliente mostrar un banner con reintento (`ErrorState`) sin confundirlo con un resultado vacío de cero ítems. | `searchCatalogResult(params)` | `SearchCatalogOutcome` (`{ status: 'error'; items: []; hasMore: false; errorCode: string }`) | Server Component error envelope propagado a `CatalogClient` como `searchError` prop. | Validated |
| **Autocompletado de cartas y sugerencias en vivo**<br/>**Given:** El visitante escribe al menos 2 caracteres en el input del header (`query.length >= 2`).<br/>**When:** Se estabiliza el debounce de 250ms y se invoca `autocompleteCatalog(...)`.<br/>**Then:** Se ejecuta la RPC `autocomplete_catalog(query, gameSlug, limit: 8)` con SECURITY DEFINER, devolviendo sugerencias (`AutocompleteHit[]`) y el indicador de desbordamiento `hasMore`. | `autocompleteCatalog(client, { query, gameSlug, limit })` | `AutocompleteResponse` (`{ hits: AutocompleteHit[]; hasMore: boolean; error: SearchError \| null }`) | Browser client directo con caché LRU de 20 entradas en `marketplace-chrome.tsx`. | Validated |
| **Registro de telemetría de demanda de búsqueda**<br/>**Given:** El visitante realiza una búsqueda en el catálogo desde el storefront con `offset === 0`.<br/>**When:** `searchCatalog` completa la primera página con éxito.<br/>**Then:** Se ejecuta en segundo plano `log_search_query(p_query, p_result_count, p_source: 'storefront')` de forma segura (best-effort, sin bloquear el render). | `logSearchQuery(client, { query, resultCount, source: 'storefront' })` | `void` (Best-effort fire-and-forget RPC) | Ejecutado automáticamente por `@chiki/search` cuando `logAnalytics: { source: 'storefront' }`. | Validated |

## Design Notes

- **Separation of Contracts**: Data contract definitions and schemas belong exclusively to `design-journey-data-model`. The BDD specification focuses strictly on runtime Service Operations and Page & Interaction Behaviors.
- **URL Synchronization**: Navigation actions synchronize `q`, `game`, `expansion`, `type`, and `stock` with the browser URL. Clearing secondary filters in the drawer maintains the current active `q` text.
- **Resilient Degraded Modes**: A failed database query surfaces a retryable error boundary rather than an empty result, preventing transient failures from being misinterpreted as zero matching items.
