# Research Capabilities

## Input

- The target journey, feature, and rule;
- `.loop/artifacts/capability-map.md`; and
- Any relevant specifications, repository paths, or reference material.

## Process

1. Read the capability map and identify capabilities, ownership decisions, and gaps already recorded for the target rule.
2. Research the targeted areas of `apps/storefront`, `apps/medusa`, and `packages` to find relevant implementations, contracts, transports, models, tests, and documentation.
3. For each finding, decide whether the delivery flow should reuse it, wrap it in `apps/storefront/apis`, migrate it, extend it, or create it. Record the owning layer and the evidence path.
4. Update `.loop/artifacts/capability-map.md` with the rule-specific findings, implementation recommendation, and unresolved gaps.

## Output

An updated `.loop/artifacts/capability-map.md` containing the target rule's capability assessment and implementation recommendations.
